# 심볼릭 링크

심볼릭 링크(Symbolic Link)는 다른 파일이나 디렉터리의 **경로를 가리키는 특수 파일**이다. Windows의 바로가기와 비슷하며, 소프트 링크(Soft Link)라고도 한다.

## 생성

```bash
ln -s 원본경로 링크이름
```

### 파일 링크

```bash
ln -s /home/user/original.txt shortcut.txt
```

### 디렉터리 링크

```bash
ln -s /var/log logs
```

`shortcut.txt`나 `logs`에 접근하면 링크가 가리키는 원본에 접근하게 된다.

## 확인

```bash
ls -l
```

출력 예시:

```text
lrwxrwxrwx 1 user user 23 Sep 17 10:00 shortcut.txt -> /home/user/original.txt
```

- 맨 앞의 `l`: 심볼릭 링크임을 의미
- `->` 뒤의 경로: 링크가 가리키는 대상

링크에 저장된 경로만 확인하려면 다음 명령어를 사용한다.

```bash
readlink shortcut.txt
```

실제 절대 경로까지 확인하려면:

```bash
readlink -f shortcut.txt
```

## 삭제

```bash
rm shortcut.txt
```

또는:

```bash
unlink shortcut.txt
```

심볼릭 링크를 삭제해도 원본 파일은 삭제되지 않는다.

> 디렉터리 링크를 삭제할 때 링크 이름 뒤에 `/`를 붙이지 않는 것이 안전하다.

## 절대 경로와 상대 경로

### 절대 경로 사용

```bash
ln -s /home/user/project/config.json config.json
```

- 링크 위치를 옮겨도 대상 경로가 유지된다.
- 다른 환경이나 사용자 디렉터리에서는 경로가 달라질 수 있다.

### 상대 경로 사용

```bash
ln -s ../project/config.json config.json
```

- 링크가 저장된 위치를 기준으로 원본을 찾는다.
- 관련 디렉터리를 함께 이동할 때 유용하다.

## 끊어진 링크

원본이 삭제되거나 이동하면 심볼릭 링크는 대상을 찾지 못하는 **끊어진 링크(Broken Link)**가 된다.

현재 디렉터리 아래의 끊어진 링크를 찾는 명령어:

```bash
find . -xtype l
```

## 하드 링크와 차이

| 구분 | 심볼릭 링크 | 하드 링크 |
|---|---|---|
| 생성 명령어 | `ln -s 원본 링크` | `ln 원본 링크` |
| 가리키는 대상 | 원본의 경로 | 원본과 동일한 inode |
| 원본 삭제 시 | 링크가 끊어짐 | 데이터에 계속 접근 가능 |
| 디렉터리 링크 | 가능 | 일반적으로 불가능 |
| 다른 파일 시스템 | 가능 | 불가능 |

## 핵심 정리

```bash
ln -s 원본 링크       # 심볼릭 링크 생성
ls -l                 # 링크와 대상 확인
readlink 링크         # 저장된 대상 경로 확인
readlink -f 링크      # 실제 절대 경로 확인
rm 링크               # 링크만 삭제
find . -xtype l       # 끊어진 링크 검색
```
