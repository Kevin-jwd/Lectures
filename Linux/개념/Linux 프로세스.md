# Linux 프로세스

## 개념

**프로그램**은 디스크에 저장된 실행 가능한 파일이고, **프로세스**는 해당 프로그램이 실행 중인 상태이다.

Linux는 여러 프로세스를 동시에 실행할 수 있는 **멀티태스킹 운영체제**이다.

## 프로세스 확인: `ps`

`ps` 명령은 현재 실행 중인 프로세스 정보를 확인할 때 사용한다.

```bash
ps
```

## PID와 PPID

각 프로세스는 **PID**와 **PPID**를 가진다.

| 항목 | 의미 |
|---|---|
| PID(Process ID) | 프로세스를 식별하는 번호 |
| PPID(Parent Process ID) | 해당 프로세스를 생성한 부모 프로세스의 PID |

## 가상 메모리와 물리 메모리

- **가상 메모리**: 프로세스와 CPU가 사용하는 논리적인 주소 공간
- **물리 메모리**: 컴퓨터에 실제로 장착된 RAM
- **MMU(Memory Management Unit)**: 가상 주소를 물리 주소로 변환하는 장치

가상 메모리 공간은 **유저 공간**과 **커널 공간**으로 구분된다.

```text
┌─────────────┐
│     CPU     │
└──────┬──────┘
       │ 가상 주소
       ▼
┌─────────────────────┐
│     가상 메모리      │
├─────────────────────┤
│ 유저 공간            │
│ - 사용자 프로세스    │
├─────────────────────┤
│ 커널 공간            │
│ - Linux 커널         │
└──────────┬──────────┘
           │
           ▼
    ┌─────────────┐
    │     MMU     │
    │ 주소 변환    │
    └──────┬──────┘
           │ 물리 주소
           ▼
┌─────────────────────┐
│      물리 메모리      │
│        RAM           │
└─────────────────────┘
```

CPU가 가상 주소를 사용하면 MMU가 이를 실제 RAM의 물리 주소로 변환한다.

## 페이지 테이블

가상 메모리는 **페이지(page)** 단위로, 물리 메모리는 같은 크기의 **페이지 프레임(page frame)** 단위로 나뉜다. **페이지 테이블**은 가상 페이지가 어느 물리 페이지 프레임에 연결되는지 기록한 표이다.

페이지 테이블은 프로세스마다 존재하며 물리 메모리에 저장된다. 각 항목을 **페이지 테이블 엔트리(PTE)**라고 한다.

| PTE 정보 | 의미 |
|---|---|
| 물리 페이지 프레임 번호 | 가상 페이지가 연결된 RAM 위치 |
| Present 비트 | 현재 물리 메모리에 존재하는지 표시 |
| 읽기·쓰기·실행 권한 | 해당 페이지에서 허용되는 접근 방식 |
| 유저·커널 접근 권한 | 유저 모드에서 접근할 수 있는지 표시 |

```text
가상 페이지        페이지 테이블          물리 페이지 프레임
┌──────────┐      ┌──────────────┐      ┌──────────┐
│ Page 0   │ ───▶ │ Frame 5      │ ───▶ │ Frame 5  │
├──────────┤      ├──────────────┤      ├──────────┤
│ Page 1   │ ───▶ │ Frame 2      │ ───▶ │ Frame 2  │
├──────────┤      ├──────────────┤      ├──────────┤
│ Page 2   │ ───▶ │ Not Present  │      │          │
└──────────┘      └──────────────┘      └──────────┘
```

## MMU의 주소 변환 순서

페이지 테이블 전체가 MMU 내부에 로딩되는 것은 아니다. 운영체제가 MMU의 페이지 테이블 기준 레지스터에 현재 프로세스의 페이지 테이블 시작 주소를 설정하고, MMU는 필요할 때 해당 테이블을 참조한다.

```text
① 프로세스 실행
      ↓
② 페이지 테이블 시작 주소를 MMU에 설정
      ↓
③ CPU가 가상 주소 생성
      ↓
④ MMU가 TLB에서 주소 변환 정보 검색
      ↓
⑤ TLB miss이면 물리 메모리의 페이지 테이블 조회
      ↓
⑥ 변환 결과를 TLB에 저장
      ↓
⑦ 물리 주소로 RAM 접근
```

**TLB(Translation Lookaside Buffer)**는 최근에 사용한 가상 페이지와 물리 페이지 프레임의 변환 결과를 MMU 내부에 저장하는 빠른 캐시이다.

### 주소 변환 예시

페이지 크기가 4KB(`0x1000`)이고 CPU가 다음 가상 주소에 접근한다고 가정한다.

```text
가상 주소: 0x00401234
```

가상 주소는 가상 페이지 번호와 페이지 내부 위치인 오프셋으로 나뉜다.

```text
가상 페이지 번호: 0x00401
페이지 오프셋:    0x234
```

페이지 테이블에 다음과 같이 기록되어 있다고 가정한다.

```text
가상 페이지 0x00401 → 물리 프레임 0x1A3
```

MMU는 물리 프레임의 시작 주소에 오프셋을 결합한다.

```text
물리 프레임 시작 주소: 0x1A3000
페이지 오프셋:         0x000234
--------------------------------
최종 물리 주소:        0x1A3234
```

변환 결과는 TLB에 저장되므로 같은 가상 페이지에 다시 접근할 때 페이지 테이블 조회를 생략할 수 있다.

페이지 테이블의 Present 비트가 `0`이면 **페이지 폴트(page fault)**가 발생한다. 커널이 필요한 페이지를 물리 메모리에 준비하고 페이지 테이블을 갱신한 뒤 명령을 다시 실행한다.

## 프로세스 생성과 실행 방법

| 방법 | 동작 | 특징 |
|---|---|---|
| `system()` | 셸을 통해 문자열로 전달한 명령 실행 | 사용이 간단하지만 셸을 거침 |
| `exec()` | 현재 프로세스를 새로운 프로그램으로 교체 | PID가 유지되며 새 프로세스를 직접 생성하지 않음 |
| `fork()` | 현재 프로세스를 복제하여 자식 프로세스 생성 | 부모와 자식이 같은 코드에서 실행을 계속함 |
| `fork()` + `exec()` | 자식 프로세스를 만든 뒤 다른 프로그램으로 교체 | Linux에서 다른 프로그램을 실행하는 일반적인 방식 |

### `system()` — [[Linux/시험/system 함수로 셸 명령 실행|시험 요약]]

```c
int system(const char *command);
```

`system()`은 `<stdlib.h>`에 선언되어 있으며, 문자열로 전달받은 명령을 셸을 통해 실행한다.

```c
#include <stdlib.h>
```

#### `system()` 동작 원리

개념적으로 `system()`은 다음 순서로 동작한다.

```text
호출 프로세스
     │
     ├─ 자식 프로세스 생성
     │        │
     │        └─ /bin/sh -c "명령 문자열" 실행
     │                     │
     │                     └─ 셸이 명령·파이프·리다이렉션 해석
     │
     └─ 자식이 끝날 때까지 대기
              │
              └─ 종료 상태를 반환
```

내부적으로는 자식 프로세스를 만든 뒤 다음과 같은 형태로 셸을 실행하는 것과 유사하다.

```c
execl("/bin/sh", "sh", "-c", command, (char *)NULL);
```

따라서 `system()`에는 단일 명령뿐 아니라 파이프(`|`)와 리다이렉션(`>`) 같은 셸 문법도 전달할 수 있다. 호출한 부모 프로세스는 셸 명령이 끝날 때까지 기다린다.

#### 반환 상태

`system()`의 반환값은 명령의 종료 코드 자체가 아니라 자식 프로세스의 **종료 상태가 인코딩된 값**이다.

| 반환 또는 확인 방법 | 의미 |
|---|---|
| `-1` | 자식 프로세스 생성 또는 대기 실패 |
| `WIFEXITED(ret)` | 명령이 정상적인 방식으로 종료되었는지 확인 |
| `WEXITSTATUS(ret)` | 정상 종료한 명령의 실제 종료 코드 추출 |

종료 상태에는 **종료 코드(exit code)**와 **종료시킨 시그널 번호**가 비트 단위로 함께 저장된다. 두 값을 단순히 더한 것이 아니라, 서로 다른 비트 영역에 인코딩한 값이다.

```text
31                         16 15          8 7           0
┌────────────────────────────┬─────────────┬─────────────┐
│          사용 안 함         │  exit code  │ signal 정보 │
└────────────────────────────┴─────────────┴─────────────┘
```

Linux의 일반적인 종료 상태 형식에서 종료 코드는 비트 `8~15`에 저장되고, 종료 시그널 번호는 하위 `7`비트에 저장된다. 하위 영역의 나머지 비트는 코어 덤프 여부 등의 정보를 나타낼 수 있다.

```text
원시 종료 상태 ≈ (exit code << 8) | signal 정보
```

| 종료 방식 | 확인 순서 | 추출하는 값 |
|---|---|---|
| `exit()` 또는 `return`으로 정상 종료 | `WIFEXITED(ret)` | `WEXITSTATUS(ret)`으로 종료 코드 추출 |
| 시그널에 의해 종료 | `WIFSIGNALED(ret)` | `WTERMSIG(ret)`으로 시그널 번호 추출 |

##### 종료 원인에 따라 하나만 유효

**exit code와 시그널 번호 중 하나만 유효하다.** 프로세스가 어떻게 종료되었는지 먼저 확인한 뒤 해당 값을 해석해야 한다.

| 종료 원인 | exit code | 시그널 번호 |
|---|---|---|
| 프로세스가 `return`, `exit()`, `_exit()`로 스스로 종료 | 유효 | 유효하지 않음 |
| 프로세스가 시그널에 의해 강제 종료 | 유효하지 않음 | 유효 |

- `WIFEXITED(ret)`이 참일 때만 `WEXITSTATUS(ret)`를 사용한다.
- `WIFSIGNALED(ret)`이 참일 때만 `WTERMSIG(ret)`를 사용한다.
- 정상 종료한 프로세스에는 종료시킨 시그널이 없다.
- 시그널로 종료된 프로세스는 정상 종료 코드를 남긴 것이 아니다.

정상 종료에서는 원시 상태의 시그널 정보 영역이 `0`이며, 시그널 번호가 아니라 종료 코드만 해석한다.

```text
종료 코드 3 → 원시 종료 상태 0x0300
```

시그널에 의해 종료되면 종료 코드는 의미가 없고, 종료 원인이 된 시그널 번호를 확인해야 한다.

```text
SIGKILL(9) → 원시 종료 상태의 시그널 번호 9
```

```c
if (ret == -1) {
    // system() 자체의 실행 실패
} else if (WIFEXITED(ret)) {
    int exit_code = WEXITSTATUS(ret);
} else if (WIFSIGNALED(ret)) {
    int signal_number = WTERMSIG(ret);
}
```

종료 상태 매크로를 사용할 때는 다음 헤더가 필요하다.

```c
#include <sys/wait.h>
```

> `system()`은 명령 문자열을 셸이 해석하므로 외부에서 받은 문자열을 그대로 전달하면 의도하지 않은 명령이 실행될 수 있다.

### `exec()`

관련 예제: [[Linux/예제/EX02-02 exec 함수 분기별 실행 결과|EX02-02 exec 함수 분기별 실행 결과]]

`exec()`는 하나의 함수가 아니라 현재 프로세스에서 새로운 프로그램을 실행하는 **함수군**이다.

```c
#include <stdio.h>  // perror()
#include <unistd.h> // exec 함수군
```

#### 동작 원리

`exec()`를 호출하면 새 프로세스를 생성하지 않고, 현재 프로세스의 실행 이미지를 새 프로그램으로 교체한다.

```text
exec() 호출 전                 exec() 호출 후
┌──────────────┐              ┌──────────────┐
│ 기존 프로그램 │              │ 새로운 프로그램│
│ code         │              │ code         │
│ data         │  exec()      │ data         │
│ heap         │ ───────────▶ │ heap         │
│ stack        │              │ stack        │
└──────────────┘              └──────────────┘
       PID ───────────────────────▶ 같은 PID
```

- 기존 프로그램의 코드, 데이터, 힙, 스택이 새 프로그램의 내용으로 교체된다.
- 새로운 프로세스를 만들지 않으므로 PID와 PPID는 유지된다.
- 현재 작업 디렉터리와 열려 있는 FD는 일반적으로 유지된다.
- `close-on-exec`가 설정된 FD는 `exec()` 실행 과정에서 닫힌다.

#### 성공과 실패

`exec()`가 성공하면 기존 프로그램은 사라지고 새 프로그램이 실행되므로 호출 다음 코드로 돌아오지 않는다.

```text
exec() 성공 → 새 프로그램 실행 → 기존 코드로 돌아오지 않음
exec() 실패 → -1 반환 → 기존 프로그램 계속 실행
```

실패하면 `-1`을 반환하고 `errno`에 오류 원인이 저장된다.

#### exec 함수군

| 함수 | 인수 전달 | 실행 파일 검색 | 환경 변수 지정 |
|---|---|---|---|
| `execl()` | 목록(list) | 경로 직접 지정 | 현재 환경 사용 |
| `execv()` | 배열(vector) | 경로 직접 지정 | 현재 환경 사용 |
| `execlp()` | 목록(list) | `PATH`에서 검색 | 현재 환경 사용 |
| `execvp()` | 배열(vector) | `PATH`에서 검색 | 현재 환경 사용 |
| `execle()` | 목록(list) | 경로 직접 지정 | 새 환경 전달 |
| `execve()` | 배열(vector) | 경로 직접 지정 | 새 환경 전달 |

함수 이름의 문자는 인수 전달 방식을 나타낸다.

| 문자 | 의미 |
|---|---|
| `l` | 인수를 나열하여 전달 |
| `v` | 인수를 배열로 전달 |
| `p` | 실행 파일을 `PATH`에서 검색 |
| `e` | 환경 변수 배열을 직접 전달 |

#### 실행 예시

```c
execl("/bin/ls", "ls", "-l", (char *)NULL);

// execl()이 실패한 경우에만 실행됨
perror("execl");
```

첫 번째 인수는 실행 파일의 경로이고, 이후 인수는 새 프로그램에 전달되는 `argv`이다. 관례적으로 첫 번째 `argv`에는 프로그램 이름을 넣으며, 인수 목록의 마지막에는 `NULL`을 전달한다.

### `fork()` *시험 출제* — [[Linux/시험/fork 함수 부모 자식 분기|시험 요약]]

관련 예제: [[Linux/예제/EX02-03 fork 함수의 부모 자식 분기|EX02-03 fork 함수의 부모 자식 분기]]

```c
pid_t fork(void);
```

`fork()`는 `<unistd.h>`에 선언되어 있으며, 현재 프로세스를 복제하여 새로운 자식 프로세스를 생성한다.

```c
#include <unistd.h>
```

#### 동작 원리

```text
부모 프로세스
     │
     └─ fork()
          ├─ 부모 프로세스: fork() 다음 코드부터 계속 실행
          └─ 자식 프로세스: fork() 다음 코드부터 계속 실행
```

`fork()`를 호출하기 전에는 프로세스가 하나지만, 성공한 뒤에는 부모와 자식 두 프로세스가 같은 코드 위치에서 각각 실행을 계속한다.

- 자식 프로세스에는 새로운 PID가 부여된다.
- 자식의 PPID는 `fork()`를 호출한 부모의 PID이다.
- 부모와 자식은 서로 독립된 가상 메모리 공간을 가진다.
- `fork()` 이후 한쪽에서 변수를 변경해도 다른 프로세스의 변수에는 영향을 주지 않는다.
- 열린 FD, 현재 작업 디렉터리, 환경 변수 등의 상태는 자식에게 상속된다.

| 반환값 | 실행 위치 |
|---:|---|
| `0` | 자식 프로세스 |
| 자식 PID | 부모 프로세스 |
| `-1` | 생성 실패 |

#### 부모와 자식 분기

```c
pid_t pid_temp = fork();

if (pid_temp == -1) {
    // 생성 실패
} else if (pid_temp == 0) {
    // 자식 프로세스
} else {
    // 부모 프로세스: pid_temp는 자식 PID
}
```

부모와 자식 중 어느 프로세스가 먼저 실행될지는 스케줄러가 결정하므로 일반적인 실행 순서는 보장되지 않는다.

#### 자식 프로세스 대기: `wait()`

관련 예제: [[Linux/예제/EX02-04 wait와 waitpid로 자식 종료 대기|EX02-04 wait와 waitpid로 자식 종료 대기]]

```c
#include <sys/wait.h>

pid_t wait(int *wstatus);
```

`wait()`는 부모 프로세스가 종료된 자식 프로세스의 상태를 회수할 때 사용한다. 종료된 자식이 없다면 자식 하나가 종료될 때까지 부모가 대기한다.

```c
int status;
pid_t child_pid = wait(&status);
```

| 반환값 | 의미 |
|---:|---|
| 자식 PID | 상태를 회수한 자식 프로세스 |
| `-1` | 대기할 자식이 없거나 오류 발생 |

`wstatus`가 필요하지 않으면 `wait(NULL)`로 호출할 수 있다. 여러 자식 중 어느 자식을 기다릴지는 지정할 수 없으며, 상태가 변한 자식 하나를 회수한다.

#### 특정 자식 대기: `waitpid()`

```c
pid_t waitpid(pid_t pid, int *wstatus, int options);
```

`waitpid()`는 기다릴 자식과 대기 방식을 지정할 수 있다.

| 인수 | 의미 |
|---|---|
| `pid > 0` | 지정한 PID의 자식 대기 |
| `pid == -1` | 임의의 자식 대기, `wait()`와 유사 |
| `options == 0` | 자식 상태가 변할 때까지 대기 |
| `WNOHANG` | 종료된 자식이 없으면 기다리지 않고 즉시 반환 |

```c
int status;
pid_t result = waitpid(child_pid, &status, 0);
```

| 반환값 | 의미 |
|---:|---|
| 자식 PID | 해당 자식의 상태를 회수함 |
| `0` | `WNOHANG` 사용 시 상태가 변한 자식이 없음 |
| `-1` | 오류 발생 |

#### 종료 상태 확인

```c
if (WIFEXITED(status)) {
    int exit_code = WEXITSTATUS(status);
} else if (WIFSIGNALED(status)) {
    int signal_number = WTERMSIG(status);
}
```

- 자식이 스스로 정상 종료하면 exit code만 유효하다.
- 자식이 시그널로 강제 종료되면 시그널 번호만 유효하다.

#### `wait()`가 필요한 이유

자식이 종료되어도 부모가 종료 상태를 회수하기 전까지 커널에는 자식의 PID와 종료 상태가 남는다. 이 상태의 자식을 **좀비 프로세스**라고 한다.

```text
자식 종료
   ↓
종료 상태 보관 → 좀비 프로세스
   ↓
부모가 wait() 또는 waitpid() 호출
   ↓
종료 상태 회수 및 자식 정보 제거
```

`wait()`와 `waitpid()`는 부모·자식의 실행 순서를 동기화하고 종료된 자식의 정보를 회수한다.

### `fork()` + `exec()`

관련 예제: [[Linux/과제/0922/EX02-06 여러 grep 자식 프로세스 실행|EX02-06 여러 grep 자식 프로세스 실행]]

```text
부모 프로세스
     │
     └─ fork() → 자식 프로세스 생성
                     │
                     └─ exec() → 새로운 프로그램으로 교체
```

`fork()`로 부모와 독립된 자식 프로세스를 만든 뒤, 자식에서 `exec()`를 호출하여 원하는 프로그램을 실행한다.
