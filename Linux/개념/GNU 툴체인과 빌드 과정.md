# GNU 툴체인과 빌드 과정

## GNU 툴체인

**툴체인(toolchain)**은 소스 코드를 빌드하여 실행 파일을 만드는 데 필요한 도구들의 집합이다. GNU, Clang, LLVM 등의 툴체인이 있으며 Linux에서는 주로 GNU 프로젝트의 툴체인을 사용한다.

### 주요 구성 요소

| 구성 요소 | 역할 |
|---|---|
| GNU Binary Utilities(Binutils) | 어셈블러 `as`, 링커 `ld` 등 프로그래밍 도구 제공 |
| GNU Compiler Collection(GCC) | 선행처리기 `cpp`, 컴파일러 `cc1` 등을 제공하며 여러 프로그래밍 언어 지원 |
| GNU C 라이브러리(glibc) | 응용 프로그램과 커널 사이의 인터페이스를 제공하는 API |
| GNU make | 빌드 과정을 자동화하는 유틸리티 |

## C 프로그램 빌드 과정

C 소스 코드는 선행처리, 컴파일, 어셈블, 링크의 네 단계를 거쳐 실행 파일이 된다.

```text
.c ──선행처리──> .i ──컴파일──> .s ──어셈블──> .o ──링크──> 실행 파일
       cpp             cc1            as             ld
```

| 단계 | 역할 | 담당 명령 | 결과물 |
|---|---|---|---|
| 선행처리(preprocess) | `#include`, `#define` 등의 지시문 처리 | `cpp` | `.i` |
| 컴파일(compile) | C 코드를 어셈블리 코드로 변환 | `cc1` | `.s` |
| 어셈블(assemble) | 어셈블리 코드를 목적 파일로 변환 | `as` | `.o` |
| 링크(link) | 목적 파일들을 결합하여 ELF 형식의 실행 파일 생성 | `ld` | 실행 파일 |

`gcc`는 전체 컴파일 과정을 관리하는 **컴파일러 드라이버**이다. 내부적으로 `cpp`, `cc1`, `as`, `ld` 등의 하위 명령을 필요한 순서로 실행한다. `gcc`만으로 전체 빌드를 수행하거나 단계별 도구와 함께 사용할 수 있다.

## GCC 빌드 옵션 *시험 출제* — [[Linux/시험/GCC 빌드 옵션|시험 요약]]

| 옵션 | 진행 단계 | 결과 |
|---|---|---|
| `-E` | 선행처리까지만 진행 | 선행처리 결과를 표준 출력으로 출력 |
| `-S` | 컴파일까지만 진행 | 어셈블리 파일 `.s` 생성 |
| `-c` | 어셈블까지만 진행 | 목적 파일 `.o` 생성 |
| 옵션 없음 | 링크까지 모두 진행 | ELF 형식의 실행 파일 생성 |
| `-o 파일명` | 생성 결과의 이름 지정 | 지정한 이름으로 결과물 생성 |
| `-save-temps` | 전체 빌드 과정 진행 | 중간에 생성되는 임시 파일을 삭제하지 않고 보존 |

### 목적 파일 생성: `-c`

```bash
aarch64-linux-gnu-gcc -c func.c
```

`-c` 옵션으로 어셈블 단계까지만 진행하므로 링크는 수행하지 않는다. `-o`를 지정하지 않으면 입력 파일의 확장자만 바꾼 `func.o`가 생성된다.

```text
func.c  →  func.o
```

### 결과 파일명 지정: `-o`

```bash
aarch64-linux-gnu-gcc -c main.c -o temp.o
```

`main.c`를 컴파일한 목적 파일의 이름을 `temp.o`로 지정한다.

```text
main.c  →  temp.o
```

### 중간 파일 보존: `-save-temps`

```bash
aarch64-linux-gnu-gcc -save-temps func.c main.c
```

전체 빌드를 수행하면서 선행처리 결과 `.i`, 어셈블리 결과 `.s`, 목적 파일 `.o` 등의 중간 파일을 삭제하지 않고 남긴다. 최종 실행 파일도 함께 생성된다.

슬라이드의 실행 결과에서는 다음 파일들을 확인할 수 있다.

```text
a-func.i  a-func.s  func.o
a-main.i  a-main.s  main.o
a.out
```

## 라이브러리

응용 프로그램은 필요한 **라이브러리**와 링크되어 실행 가능한 프로그램이 된다. 라이브러리는 여러 프로그램에서 재사용할 수 있도록 함수와 코드를 모아 둔 파일이다.

### 정적 라이브러리와 공유 라이브러리

| 구분 | 정적 라이브러리 | 공유 라이브러리 |
|---|---|---|
| 링크 시점 | 빌드의 링크 단계 | 프로그램 실행 시점 |
| 포함 방식 | 필요한 코드가 실행 파일에 포함됨 | 실행 파일이 외부 라이브러리를 참조함 |
| 실행 파일 크기 | 상대적으로 큼 | 상대적으로 작음 |
| 메모리 사용 | 프로그램마다 라이브러리 코드가 포함됨 | 여러 프로그램이 같은 라이브러리를 공유할 수 있어 효율적 |
| 파일명 형식 | `lib이름.a` | `lib이름.so` |

라이브러리는 정적 라이브러리와 공유 라이브러리 형태를 모두 제공할 수 있다. Linux에서는 별도의 옵션이 없다면 일반적으로 공유 라이브러리 링크가 기본이다.

```text
정적 라이브러리: libexample.a
공유 라이브러리: libexample.so
```

### 공유 라이브러리의 파일명 구조 *시험 출제* — [[Linux/시험/공유 라이브러리 파일명 구조|시험 요약]]

공유 라이브러리는 역할에 따라 **링크 이름**, **SONAME**, **실제 파일명**의 세 가지 이름을 사용한다.

```text
링크 이름                SONAME                 실제 파일명
libmycal.so  →  libmycal.so.1  →  libmycal.so.1.2
```

| 구분 | 예시 | 역할 |
|---|---|---|
| 링크 이름(link name) | `libmycal.so` | 빌드할 때 링커가 라이브러리를 찾는 이름 |
| SONAME | `libmycal.so.1` | 응용 프로그램에 기록되는 호환 버전 이름 |
| 실제 파일명(real name) | `libmycal.so.1.2` | 라이브러리 코드가 들어 있는 실제 파일 |

링크 이름과 SONAME 파일은 일반적으로 실제 라이브러리 파일을 가리키는 [[Linux/개념/심볼릭 링크|심볼릭 링크]]로 구성한다.

빌드할 때 `gcc`의 링커는 링크 이름인 `libmycal.so`를 찾지만, 생성된 응용 프로그램에는 필요한 공유 라이브러리의 SONAME인 `libmycal.so.1`이 기록된다. 프로그램을 실행하면 동적 링커가 이 SONAME 파일을 찾고, 연결된 실제 파일 `libmycal.so.1.2`를 메모리에 로드한다.

## GNU make

`make`는 프로그램의 빌드 과정을 자동화하는 유틸리티이다. 프로그램의 기능과 구조가 복잡해져 실행 파일을 만드는 절차가 길어질 때 사용한다.

`make`는 변경된 파일에 필요한 작업만 다시 수행하므로 전체를 매번 컴파일하는 것보다 재빌드 시간을 줄일 수 있다.

### Makefile *시험 출제* — [[Linux/시험/Makefile 핵심|시험 요약]]

**Makefile**은 `make`가 수행할 작업과 순서를 규칙으로 작성한 파일이다. 다음과 같은 정해진 이름을 사용할 수 있다.

- `Makefile` — 권장 이름
- `makefile`
- `GNUmakefile`

다른 이름을 사용했다면 `-f` 옵션으로 파일을 지정한다.

```bash
make -f 빌드파일명
```

### 규칙 구조

Makefile은 **타깃**, **의존 파일**, **명령**으로 구성된 규칙들을 포함한다.

```makefile
타깃: 의존파일1 의존파일2
	명령1
	명령2
```

- **타깃(target)**: 생성할 실제 파일 또는 `all`, `clean`과 같은 작업 이름
- **의존 파일(prerequisite)**: 타깃을 만들 때 필요한 파일 또는 다른 규칙의 타깃
- **명령(recipe)**: 타깃을 만들기 위해 실행할 명령

> 명령 줄 앞에는 공백이 아니라 반드시 **Tab 문자**를 사용한다.

### 타깃 실행

타깃을 지정하지 않고 `make`를 실행하면 Makefile의 첫 번째 규칙을 실행한다.

```bash
make
```

특정 타깃을 지정하면 해당 규칙을 찾아 실행한다.

```bash
make clean
```

의존 항목이 다른 규칙의 타깃이면 먼저 그 규칙을 실행한 뒤 원래 타깃으로 돌아온다.

### 명령 실행 조건

파일을 생성하는 타깃의 명령은 다음 경우에 실행된다.

- 타깃 파일이 존재하지 않을 때
- 의존 파일 중 하나가 타깃 파일보다 새로울 때

`all`, `clean`처럼 실제 파일을 만들지 않는 작업 이름은 **레이블 타깃**으로 사용한다. 같은 이름의 파일 때문에 실행이 생략되지 않도록 일반적으로 `.PHONY`로 선언한다.

```makefile
.PHONY: all clean
```

## 핵심 정리

- GNU 툴체인은 Binutils, GCC, glibc, make 등의 도구로 구성된다.
- C 프로그램은 `.c → .i → .s → .o → 실행 파일` 순서로 빌드된다.
- `gcc`는 각 단계의 하위 도구를 실행하고 전체 빌드 과정을 관리한다.
- `-E`, `-S`, `-c`로 빌드를 원하는 단계에서 멈출 수 있다.
- `-o`는 결과 파일명을 지정하고, `-save-temps`는 중간 파일을 보존한다.
- 정적 라이브러리는 실행 파일에 포함되고, 공유 라이브러리는 실행 시 외부 라이브러리와 연결된다.
- 정적 라이브러리는 `.a`, 공유 라이브러리는 `.so` 확장자를 사용한다.
- 공유 라이브러리는 링크 이름, SONAME, 실제 파일명의 구조로 버전과 호환성을 관리한다.
- `make`는 Makefile의 규칙을 읽고 변경이 필요한 부분만 다시 빌드한다.
- Makefile의 규칙은 타깃, 의존 파일, Tab으로 시작하는 명령으로 구성된다.
- 타겟과 의존파일들이 모두 실제 파일이고 이 중 타겟이 가장 최신 파일이면 명령들은 실행되지 않음 -> 이 외의 경우 명령들은 무조건 실행됨
