## VFS(Virtual File System)

**VFS**는 서로 다른 파일시스템을 응용 프로그램이 공통된 방식으로 사용할 수 있게 하는 커널의 추상 계층이다. 응용 프로그램은 파일시스템 종류마다 다른 함수를 호출하지 않고 `open()`, `read()`, `write()` 같은 공통 인터페이스를 사용한다.

```text
응용 프로그램 → open(), read(), write() → VFS → 실제 파일시스템
                                           ├─ ext4
                                           └─ 다른 파일시스템
```

## VFS의 4가지 객체 *시험 출제*

| 객체 | 나타내는 것 | 주요 역할 |
|---|---|---|
| **superblock (`super_block`)** | 마운트된 파일시스템 전체 | 파일시스템의 크기·블록 크기 등 전체 정보 관리 |
| **inode (`inode`)** | 개별 파일·디렉터리 | 파일 종류, 권한, 소유자, 크기 등 메타데이터 관리. **파일 이름은 포함하지 않음** |
| **dentry (`dentry`)** | 디렉터리 안의 이름과 경로 구성 요소 | 이름을 inode에 연결하고 경로 탐색에 사용 |
| **file (`file`)** | 프로세스가 연 파일 | 열린 파일의 접근 모드·현재 읽기/쓰기 위치 등을 관리 |

```text
마운트된 파일시스템 ── super_block
                          │
경로 /dir/a.txt ── dentry(이름·경로) ── inode(파일 자체의 정보)
                          │
프로세스의 파일 디스크립터 ── file(열린 상태·현재 위치)
```

`open()`으로 파일을 열면 프로세스는 **파일 디스크립터**를 받으며, 이 번호를 통해 열린 파일의 `file` 객체에 접근한다. 같은 파일을 여러 번 열면 동일한 파일의 inode를 가리키더라도 열린 상태를 나타내는 `file` 객체는 각각 생길 수 있다.

## 핵심 구별

- **superblock**: 파일시스템 전체
- **inode**: 파일의 메타데이터
- **dentry**: 파일의 이름과 경로 연결
- **file**: 파일을 연 뒤의 상태
