

## 1. LCD1602A 하드웨어 구성 (Hardware Configuration)

LCD1602A는 **16열 × 2행(총 32문자)**을 표시하는 문자형 LCD이다.

- **LCD Controller:** HD44780 호환 컨트롤러
    
- **I2C Expander:** PCF8574T
    
- **I2C Address:** `0x27` (현재 프로젝트 설정)
    
- **Platform:** NVIDIA Jetson Orin Nano
    

### Jetson과 LCD 모듈 연결

PCF8574T I2C 변환 모듈을 사용하므로 Jetson에서는 4개의 연결선만 필요하다.

|PCF8574T 모듈|Jetson 헤더|역할|
|---|---|---|
|VCC (Vin)|5V 전원|모듈 전원 공급|
|GND|GND|공통 접지|
|SDA|27번|I2C 데이터|
|SCL|28번|I2C 클록|

현재 프로젝트에서는 BMP180과 LCD가 각각 다른 I2C 버스를 사용한다.

- BMP180: I2C-7 (3번 SDA, 5번 SCL)
    
- LCD1602A: I2C-1 (27번 SDA, 28번 SCL)

---

## 2. PCF8574T의 역할 (I2C I/O Expander)

LCD1602A는 본래 RS, R/W, E, DB0~DB7 등을 사용하는 병렬 인터페이스를 지원한다.

하지만 현재 프로젝트에서는 **PCF8574T I2C 확장 모듈이 LCD의 병렬 제어를 대신 수행**한다.

### 전체 통신 구조

1. Jetson에서 I2C 명령 전송
    
2. PCF8574T가 I2C 데이터 수신
    
3. PCF8574T의 출력 핀(P0~P7) 상태 변경
    
4. LCD1602A가 명령어 또는 문자 데이터 처리
    
5. LCD 화면에 문자 출력
    

### PCF8574T의 출력 핀 매핑

현재 `fan_lcd_hw.c` 기준:

|PCF8574T 출력|LCD 제어 신호|역할|
|---|---|---|
|P0|RS|명령어 / 문자 데이터 선택|
|P1|R/W|읽기 / 쓰기 선택|
|P2|E|데이터 래치|
|P3|Backlight|백라이트 ON/OFF|
|P4~P7|DB4~DB7|4-bit 데이터 전송|

이 출력 핀들은 PCF8574T 모듈과 LCD 사이에 연결되어 있으며 Jetson에 별도로 배선할 필요가 없다.

현재 드라이버에서는 R/W를 LOW로 유지하여 쓰기 전용 방식으로 LCD를 제어한다.

---

## 3. 4-bit 데이터 전송 (4-bit Data Transfer)

Jetson과 PCF8574T는 I2C로 통신하지만, **PCF8574T와 LCD1602A 사이에서는 4-bit 병렬 인터페이스를 사용**한다.

LCD로 전달할 8비트 명령어 또는 문자 데이터는 상위 4비트와 하위 4비트로 나누어 전송한다.

### 데이터 전송 흐름

1. **Prepare Data** — LCD에 전달할 명령어 또는 문자 데이터 준비
    
2. **High Nibble** — 상위 4비트를 PCF8574T 출력에 반영
    
3. **Enable Pulse** — E 신호를 LOW → HIGH → LOW로 변경
    
4. **Low Nibble** — 하위 4비트를 출력에 반영
    
5. **Enable Pulse** — 다시 E 신호를 변경하여 전송 완료
    

### 주요 함수

|함수|역할|
|---|---|
|`fan_lcd_output()`|PCF8574T로 I2C 데이터 전송|
|`fan_lcd_write_nibble()`|4비트 데이터와 Enable 신호 전송|
|`fan_lcd_write_byte()`|8비트 데이터를 두 번에 나눠 전송|
|`fan_lcd_command()`|명령어 전송|
|`fan_lcd_write_char()`|문자 데이터 전송|

## 4. LCD 초기화 과정 (Initialization Sequence)

데이터시트의 4-bit Initialization Sequence에 따라 LCD를 초기화한다.

|순서|명령|역할|
|---|---|---|
|1|50ms 대기|전원 안정화|
|2|`0x30` × 3|초기 인터페이스 설정|
|3|`0x20`|4-bit 인터페이스 전환|
|4|`0x28`|4-bit, 2행, 5×8 폰트|
|5|`0x08`|화면 OFF|
|6|`0x01`|화면 초기화|
|7|`0x06`|문자 입력 시 주소 증가|
|8|`0x0C`|화면 ON, 커서 OFF|

초기화 과정에서는 각 명령어 사이에 데이터시트에서 요구하는 대기시간을 적용한다.

**관련 함수:** `fan_lcd_initialize()`

**데이터시트:** p.17

## 5. LCD 타이밍 제어 (Timing Characteristics)

LCD1602A는 명령어 실행시간과 Enable 신호의 타이밍을 만족해야 한다.

|항목|데이터시트|드라이버 구현|
|---|---|---|
|Enable Cycle|최소 500ns|I2C 전송 및 지연|
|Enable HIGH Pulse|최소 230ns|`udelay(1)`|
|일반 명령 실행시간|약 39µs|`usleep_range(50,100)`|
|Clear / Return Home|약 1.53ms|`msleep(2)`|

현재 드라이버에서는 LCD의 Busy Flag를 직접 읽지 않고 명령별 대기시간을 적용한다.

**관련 함수:** `fan_lcd_write_nibble()`, `fan_lcd_command()`

**데이터시트:** p.13~14

## 6. DDRAM 기반 문자 출력 (DDRAM Addressing)

LCD1602A 내부 DDRAM에는 화면에 표시할 문자 코드가 저장된다.

16×2 LCD는 행마다 DDRAM 주소가 다르다.

|구분|DDRAM 주소|주소 설정 명령|
|---|---|---|
|1행|`0x00~0x0F`|`0x80~0x8F`|
|2행|`0x40~0x4F`|`0xC0~0xCF`|

### 부분 출력 (Partial Update)

현재 프로젝트에서는 `pwrite()`의 Offset을 LCD의 DDRAM 주소로 변환한다.

- Offset 0~15: 첫 번째 행
    
- Offset 16~31: 두 번째 행
    

이를 통해 화면 전체를 초기화하지 않고 특정 영역만 갱신한다.

예시:

```
AUTO    00:30:00
24.6°C       ROT
```

- 모드 표시
    
- 타이머 표시
    
- 온도 표시
    
- 회전 상태 표시
    

**관련 함수:** `fan_lcd_set_cursor()`, `fan_lcd_write()`

**데이터시트:** p.10

## 7. Linux Character Device Driver 구현

현재 LCD 드라이버는 **I2C Client Driver와 Character Device를 결합한 구조**로 구현되어 있다.

### Device Tree 등록

```
lcd1602a@27 {
    compatible = "kcci,lcd1602";
    reg = <0x27>;
};
```

해당 노드는 `/bus@0/i2c@c240000` 컨트롤러에 등록된다.

### probe() 초기화 과정

1. Device Tree와 I2C Driver 매칭
    
2. `probe()` 함수 호출
    
3. I2C 통신 기능 확인
    
4. 드라이버 데이터 구조체 초기화
    
5. LCD 초기화 명령 전송
    
6. Character Device 등록
    

### 사용자 공간 인터페이스

|시스템 콜|역할|
|---|---|
|`open()`|LCD 장치 열기|
|`write()`|문자 출력|
|`pwrite()`|지정 위치에 문자 출력|
|`ioctl()`|화면 초기화 및 백라이트 제어|
|`close()`|장치 닫기|

등록된 장치 파일:

`/dev/lcd1602`

### 동시 접근 및 리소스 관리

- `mutex`: I2C 전송 순서 보호
    
- `kref`: 장치 데이터의 수명 관리
    
- `online`: 드라이버 제거 후 접근 차단
    
- 통신 실패 시 오류 코드 반환

## 8. End-to-End LCD 출력 흐름

1. **Application**
    
    - 사용자 프로그램에서 `pwrite()` 호출
        
2. **Character Device**
    
    - `/dev/lcd1602`를 통해 쓰기 요청 전달
        
3. **LCD Driver**
    
    - 문자열 수신
        
    - 출력 위치 계산
        
    - 명령어 및 문자 데이터를 4비트 단위로 분할
        
4. **Linux I2C Core**
    
    - I2C 컨트롤러를 통해 데이터 전송
        
5. **PCF8574T**
    
    - I2C 데이터를 수신하여 LCD 제어 신호 생성
        
6. **LCD1602A**
    
    - DDRAM에 문자 코드 기록
        
    - 화면 출력
        

### 전체 구조

```
[Application]
      │
      │ pwrite() / ioctl()
      ▼
[/dev/lcd1602]
      │
      ▼
[Linux Character Device Driver]
      │
      │ i2c_smbus_write_byte()
      ▼
[Jetson I2C Controller]
      │
      │ SDA / SCL
      ▼
[PCF8574T I2C Expander]
      │
      │ RS / E / DB4~DB7
      ▼
[LCD1602A]
      │
      ▼
[문자 출력]
```
