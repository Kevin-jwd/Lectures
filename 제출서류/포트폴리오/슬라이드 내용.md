## 01. Vision Tracker — 프로젝트 개요

### Jetson–STM32 기반 실시간 인물 추적 시스템

선택한 인물을 카메라가 자동으로 추적하고, 게임패드로 차량 위치를 수동 제어하는 임베디드 시스템입니다.

**주요 기능**

- 영상에서 인물을 검출하고 선택한 대상의 ID 유지
    
- 가림이나 화면 이탈 이후 대상 재검색 및 재연결
    
- 대상 위치에 따른 팬·틸트 카메라 제어
    
- 게임패드를 이용한 차량 방향·속도 제어
    
- 웹 화면을 통한 영상 및 제어 상태 확인
    

**개발 환경**

Jetson, STM32, Python, C, TensorRT, OpenCV, FastAPI, UART

**담당 역할**

[본인이 맡은 추적 알고리즘·통신·시스템 통합·펌웨어 항목 기입]

## 02. Vision Tracker — 시스템 설계

### 영상 처리와 차량 제어의 처리 주기 분리

AI 추론 시간이 길어져도 차량 입력 처리에 영향을 주지 않도록 영상 처리와 게임패드 제어를 분리했습니다.

**최신 프레임 기반 영상 처리**

- 카메라 캡처와 AI 추론을 별도 스레드로 구성
    
- AI 처리가 끝나면 가장 최신 프레임을 가져와 처리
    
- 오래된 프레임의 누적으로 발생하는 영상 지연 억제
    

**UART 송신 경로 통합**

- 차량과 팬·틸트 명령을 하나의 제어 서비스에서 송신
    
- 여러 작업자가 동시에 송신하며 패킷을 섞는 상황 방지
    
- STM32에서 패킷 종류와 무결성을 검증한 뒤 명령 적용
    

**STM32 구동 제어**

- 타이머 PWM을 이용한 팬·틸트 및 차량 출력 제어
    
- 차량 명령 수신 중단 시 타임아웃에 따른 정지 처리
    
- 방향 반전 대기와 출력 변화량 제한 적용

## 03. Vision Tracker — 추적 안정성과 문제 해결

### 대상 ID 변경과 제어 신호 불안정 개선

**문제 1. 가림과 교차 이동 중 추적 대상 변경**

BoT-SORT의 추적 ID와 사용자에게 표시하는 ID를 분리하고, OSNet 특징을 이용해 대상을 다시 연결했습니다.

- 후보 간 유사도 차이와 연속 일치 조건으로 재연결 판단
    
- 가려지거나 화면 경계에서 잘린 이미지는 특징 저장에서 제외
    
- 대상 불일치 시 팬·틸트 추적을 멈추고 재검색
    

**문제 2. AI 처리 지연에 따른 영상 누적**

캡처와 추론을 분리하고 최신 프레임만 처리하도록 변경했습니다. 프레임 나이와 처리 시간을 측정해 지연을 확인하는 기준을 마련했습니다.

**문제 3. 서보 초기화 과정의 출력 글리치**

GPIO를 Low로 유지한 상태에서 타이머와 초기 펄스 폭을 설정한 뒤 PWM 출력을 연결하도록 초기화 순서를 변경했습니다.

**개발 경험**

영상 처리 지연과 추적 상태를 실제 구동 명령에 연결하며, 비동기 작업 간 통신과 오류 복구 구조를 설계했습니다.

## 05. Fan Linux Driver — 드라이버와 애플리케이션 구조

### 장치 접근과 제어 정책의 계층 분리

커널 드라이버는 장치 접근을 담당하고, 사용자 공간 애플리케이션은 입력 이벤트와 운전 상태를 관리하도록 구성했습니다.

**커널 드라이버**

- 디바이스 트리에서 장치와 하드웨어 자원 정의
    
- BMP180의 측정값을 보정해 사용자 공간에 제공
    
- LCD 문자 출력과 백라이트 제어 인터페이스 구현
    
- read, poll, ioctl을 이용한 장치별 접근 방식 구성
    

**사용자 공간 애플리케이션**

- 입력·타이머·센서 처리를 별도 스레드로 분리
    
- mutex로 공유 상태 접근 보호
    
- FSM에서 전원·운전 모드·예약 종료 상태 관리
    

**입력 이벤트 전달**

커널의 이벤트 큐와 대기 큐를 이용해 입력을 전달하고, 애플리케이션에서 poll로 이벤트를 기다리는 구조를 적용했습니다.

- 화면 전체를 지우는 동작을 줄여 깜빡임을 줄이는 구조 적용
    

**드라이버·앱 통합**

- 입력 이벤트 수신 API와 FSM 처리 연결
    
- 빌드 대상 및 헤더 의존성 정리
    
- 장치 등록 방식에 맞춰 모듈 적재·해제 흐름 수정
    

**개발 경험**

센서 드라이버와 사용자 공간 API를 연결하고, 개별 장치 구현 이후 발생하는 빌드·등록·통합 문제를 해결했습니다.

## 08. 차량 HMI — 통신과 멀티스레드 설계

### UART 수신 처리와 카메라 작업 분리

**UART 메시지 조립**

UART 데이터가 여러 번에 나뉘어 도착하는 상황을 고려해 수신 데이터를 버퍼에 누적했습니다.

- 개행을 기준으로 완성된 메시지만 분리
    
- 메시지 종류에 따라 센서·주행·환경 이벤트 전달
    
- 비정상적으로 누적되는 버퍼에 크기 제한 적용
    
- 주기적인 하트비트 송신 구현
    

**카메라 처리 구조**

- 카메라별 캡처 스레드 하나에서 프레임 공급
    
- 표시와 얼굴 인식을 별도 작업으로 분리
    
- 같은 카메라를 중복으로 여는 상황 방지
    
- 종료 시 소비자 작업을 먼저 정리한 뒤 캡처 종료
    

**DB 접근 구조**

워커 스레드의 결과를 시그널로 전달하고, UI 스레드에서 DB 저장을 처리해 연결의 스레드 소유권을 유지했습니다.
