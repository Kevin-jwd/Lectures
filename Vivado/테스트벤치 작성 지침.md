# 테스트벤치 작성 지침

[[Vivado/테스트벤치와 시뮬레이션]]의 수업 내용을 작성 순서 중심으로 요약했다. **Verilog 테스트벤치 기준**이며, 전체 Gates 예제와 예상 파형은 기존 노트에서 확인한다.

## 1. Simulation Source로 추가

`Add Sources` → `Add or Create Simulation Sources` → `Create File`에서 Verilog 파일을 만든다.

- 실제 회로(DUT)는 **Design Sources**, 테스트벤치는 **Simulation Sources**에 둔다.
- 테스트벤치 모듈은 외부 입출력 포트 없이 작성한다.
- 시뮬레이션의 최상위 모듈은 테스트벤치로 지정한다.

## 2. 시간 단위 지정

```verilog
`timescale 1ns / 1ps
```

앞은 **시간 단위**, 뒤는 **시간 정밀도**이다. 위 설정에서 `#10`은 10 ns 지연이다.

## 3. DUT에 연결할 신호 선언

- 테스트벤치에서 값을 넣을 **DUT 입력용 신호는 `reg`**로 선언한다.
- DUT가 출력하는 값을 받을 **출력 관찰용 신호는 `wire`**로 선언한다.
- 신호의 비트 폭은 DUT 포트와 맞춘다.

**DUT 포트의 방향을 기준으로 판단**한다. DUT의 입력은 테스트벤치가 구동하고, DUT의 출력은 테스트벤치가 관찰한다.

## 4. DUT 인스턴스 연결

모듈 이름과 인스턴스 이름을 구분하고, **포트 이름을 지정하는 named instantiation**으로 연결한다.

기존 Gates 예제의 연결 일부는 다음과 같다.

```verilog
.a(i_a),  // DUT의 a 포트 ← 테스트벤치의 i_a 신호
.b(i_b)   // DUT의 b 포트 ← 테스트벤치의 i_b 신호
```

포트 이름과 테스트벤치 신호 이름은 같을 필요가 없다. 모듈 이름·포트 이름의 철자와 대소문자는 실제 DUT 정의와 일치시킨다.

## 5. initial에서 입력 자극 작성

**시작 값을 먼저 지정하고, 시간을 진행시키며 입력을 바꾼다.** 이 수업의 순차적인 입력 설정에는 블로킹 할당 `=`을 사용한다.

```verilog
initial begin
    i_a = 1'b0; i_b = 1'b0;
    #10 i_a = 1'b0; i_b = 1'b1;
    #10 i_a = 1'b1; i_b = 1'b0;
    #10 i_a = 1'b1; i_b = 1'b1;
    #10 $finish;
end
```

- 두 입력의 게이트 회로라면 `00 → 01 → 10 → 11`의 **모든 입력 조합**을 확인한다.
- `#10`은 절대 시각이 아니라 **직전 단계에서 10 ns를 더 기다림**을 뜻한다.
- 마지막 입력도 관찰할 시간을 준 뒤 `$finish`로 종료한다.
- 위 입력 자극은 [[디지털 논리 회로/조합논리와 순차논리|조합논리]] 검증용이며, 클록이 필요한 순차회로에서는 클록·리셋 자극도 준비한다.

## 6. 실행하고 예상 결과와 비교

`Run Simulation` → `Run Behavioral Simulation`을 실행한다.

**파형이 나오는 것만으로 검증이 끝나는 것은 아니다.** 입력 변경 시점마다 출력이 진리표·설계 의도와 맞는지 비교한다.
