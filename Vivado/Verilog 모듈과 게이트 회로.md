# Verilog 모듈과 게이트 회로

출처: PDF 12–13, 33–36쪽 · [[Vivado/00 Vivado 디지털 회로 설계 길잡이|길잡이]]

## 모듈과 포트

**모듈은 회로를 구성하는 기본 단위**이며, 내부 동작과 외부 연결 포트를 정의한다. 여러 모듈을 연결하여 큰 회로를 만들 수 있다.

| 문법 | 역할 |
|---|---|
| `module` / `endmodule` | 모듈 정의 시작·종료 |
| `input` | 입력 포트 |
| `output` | 출력 포트 |
| `inout` | 양방향 포트 |
| `assign` | 연속 할당으로 논리 연결을 기술 |
| `always` | 이벤트에 따라 반복 실행되는 동작 기술 |
| `initial` | 시뮬레이션 시작 시 한 번 실행되는 동작 기술 |
| `begin` / `end` | 여러 문장을 하나의 블록으로 묶음 |

키워드는 소문자로 작성한다. 버스 포트는 여러 비트를 묶은 포트이다.

```verilog
output [3:0] o_s;  // 4비트 출력 포트
```

## 모델링 방식: Behavioral과 Dataflow

요청에 따라 추가한 보충 개념이다. **모델링 방식은 회로를 코드로 표현하는 방법**이다. 같은 회로도 서로 다른 방식으로 기술할 수 있다.

| 구분 | Behavioral(동작적 모델링) | Dataflow(데이터 흐름 모델링) |
|---|---|---|
| 표현 중심 | 어떤 조건·이벤트에서 어떤 동작을 하는가 | 입력과 출력 사이에 어떤 논리식이 성립하는가 |
| 대표 구문 | `always`, `initial`, `if`, `case` | `assign`과 논리·산술·조건 연산자 |
| 할당 형태 | 절차 블록 안에서 `=` 또는 `<=` | 연속 할당 `assign` |
| 주로 사용하는 곳 | 조건이 복잡한 조합논리, 클록 기반 순차논리, 테스트벤치 | 논리식으로 표현하기 쉬운 조합논리 |

### Behavioral: 동작을 절차로 기술

`always` 블록의 실행 조건과 내부 문장으로 동작을 표현한다. **Behavioral이 곧 순차회로라는 뜻은 아니다.** 조합논리와 순차논리를 모두 기술할 수 있다.

```verilog
// 조합논리: 2입력 멀티플렉서
module mux_behavioral(
    input a,
    input b,
    input sel,
    output reg y
);
    always @(*) begin
        if (sel)
            y = b;
        else
            y = a;
    end
endmodule
```

- `always @(*)`: 블록에서 읽는 입력이 변하면 동작을 다시 평가한다.
- `if`로 선택 조건을 표현한다. 위 코드는 **모든 조건에서 y를 할당**하므로 조합논리를 표현한다.
- Verilog에서 절차적으로 할당하는 y는 `reg`로 선언한다. **`reg` 선언만으로 플립플롭이 되는 것은 아니다.**
- 클록 에지를 기준으로 상태를 저장하려면 아래처럼 기술한다.

```verilog
always @(posedge clk) begin
    q <= d;
end
```

이는 클록 상승 에지에서 값을 저장하는 플립플롭 동작이다. 저장 소자 구분은 [[디지털 논리 회로/조합논리와 순차논리#플립플롭과 래치|플립플롭과 래치]], 입력 자극을 만드는 `initial`은 [[Vivado/테스트벤치 작성 지침]]을 참고한다.

### Dataflow: 데이터의 논리 관계를 식으로 기술

**`assign`으로 출력과 입력 사이의 관계를 연속적으로 정의**한다. 오른쪽 입력이 바뀌면 식을 다시 평가하여 출력에 반영한다.

```verilog
// 위 Behavioral 예제와 같은 멀티플렉서
module mux_dataflow(
    input a,
    input b,
    input sel,
    output y
);
    assign y = sel ? b : a;
endmodule
```

- `sel`이 1이면 b, 0이면 a를 선택한다.
- 연속 할당으로 구동하는 y는 net이며, 위 Verilog 선언에서는 기본적으로 `wire`이다.
- `assign` 여러 줄은 프로그램의 순차 실행이 아니라 **각 신호의 논리 관계**를 나타낸다.
- 아래 Gates 예제와 [[디지털 논리 회로/반가산기와 전가산기|가산기의 논리식]]도 Dataflow 방식으로 표현할 수 있다.

### 구분할 때 주의할 점

- **Behavioral은 동작·조건 중심, Dataflow는 논리식·데이터 관계 중심**이다.
- 문법이 달라도 동작이 같고 합성 가능하다면 같은 회로로 합성될 수 있다. 두 멀티플렉서 예제 모두 **sel=0이면 a, sel=1이면 b**를 출력한다.
- Behavioral의 문장 순서는 시뮬레이션 규칙에 따라 의미가 있지만, 모든 문장이 실제 하드웨어에서 시간 순서대로 실행된다는 뜻은 아니다.
- Vivado의 **`Run Behavioral Simulation`은 합성 전 RTL 시뮬레이션 단계의 이름**이다. Behavioral 코드만 실행한다는 뜻이 아니며 Dataflow 코드도 함께 검증한다.

블로킹·논블로킹의 갱신 순서는 아래 할당 설명, 회로 변환 과정은 [[Vivado/합성과 구현]]으로 연결해서 확인한다.

## 게이트 프리미티브(Gate Primitive)

요청에 따라 추가한 보충 개념이다. **Verilog가 기본 제공하는 논리 게이트를 직접 인스턴스화하는 문법**이다. 별도로 게이트의 module을 정의하지 않아도 사용할 수 있다.

게이트와 신호의 연결을 직접 기술하므로 **구조적(Structural), 게이트 수준(Gate-level) 모델링**에 해당한다.

### 기본 종류

| 프리미티브 | 동작 | 포트 구성 |
|---|---|---|
| `and` | 입력이 모두 1이면 1 | 출력 1개, 입력 여러 개 |
| `or` | 입력 중 하나라도 1이면 1 | 출력 1개, 입력 여러 개 |
| `nand` | AND 결과 반전 | 출력 1개, 입력 여러 개 |
| `nor` | OR 결과 반전 | 출력 1개, 입력 여러 개 |
| `xor` | 입력 중 1의 개수가 홀수이면 1 | 출력 1개, 입력 여러 개 |
| `xnor` | 입력 중 1의 개수가 짝수이면 1 | 출력 1개, 입력 여러 개 |
| `not` | 입력 반전 | 출력 하나 이상, 마지막 포트가 입력 1개 |
| `buf` | 입력을 그대로 전달 | 출력 하나 이상, 마지막 포트가 입력 1개 |

진리표: [[디지털 논리 회로/AND OR NAND NOR]], [[디지털 논리 회로/XOR과 XNOR]], [[디지털 논리 회로/NOT과 버퍼]].

### 문법과 포트 순서

```verilog
// 기본 논리 게이트: 게이트종류 인스턴스이름 (출력, 입력1, 입력2, ...);
and u_and(y, a, b);
not u_not(inverted, a);
```

- **출력이 먼저, 입력이 뒤**에 온다. `and u_and(a, b, y);`처럼 입력부터 적지 않도록 주의한다.
- `u_and`는 인스턴스 이름이다. 생략할 수 있지만 구분과 회로 확인을 위해 이름을 붙이면 편리하다.
- 기본 게이트 프리미티브는 **위치 기반 포트 연결**을 사용한다. 모듈 인스턴스처럼 `.포트명(신호)`로 연결하지 않는다.
- 출력은 일반적으로 `wire`인 net에 연결한다. 기본 게이트의 입력은 최소 개수 이상으로 늘릴 수 있다.

```verilog
and u_and3(y, a, b, c);  // 3입력 AND
```

### Gates 회로를 프리미티브로 표현

아래 Dataflow Gates 모듈과 같은 입출력 동작을 표현한다.

```verilog
module Gates_primitive(
    input a,
    input b,
    output ld0,
    output ld1,
    output ld2,
    output ld3,
    output ld4,
    output ld5
);
    and  u_and (ld0, a, b);
    or   u_or  (ld1, a, b);
    nand u_nand(ld2, a, b);
    nor  u_nor (ld3, a, b);
    xor  u_xor (ld4, a, b);
    not  u_not (ld5, a);
endmodule
```

### 세 모델링 방식의 관계

| 방식 | AND 회로 표현 예 | 중심 |
|---|---|---|
| Behavioral | `always @(*) y = a & b;` | 동작을 절차 블록으로 기술 |
| Dataflow | `assign y = a & b;` | 입력·출력의 논리 관계 |
| Structural / Gate-level | `and u_and(y, a, b);` | 게이트와 연결 구조 |

위 표에서 Behavioral의 y는 절차 할당용 `reg`, 나머지 y는 net으로 선언한다. **세 표현은 같은 AND 기능을 만들 수 있으며, 프리미티브로 작성했다고 반드시 FPGA의 별도 AND 소자가 그대로 배치되는 것은 아니다.** 실제 자원 매핑은 [[Vivado/합성과 구현]] 과정에서 결정된다.

## 결합 연산자와 반복 연산자

요청에 따라 추가한 Verilog 보충 문법이다. **두 연산자 모두 비트를 이어 붙여 하나의 벡터를 만든다.** 덧셈이나 반복 실행을 의미하지 않는다.

### 결합 연산자(Concatenation)

중괄호 안에 여러 신호를 쉼표로 나열한다. **왼쪽 항목이 상위 비트, 오른쪽 항목이 하위 비트**가 된다. 결과 폭은 각 항목의 비트 폭을 합한 값이다.

```verilog
// 문법: {항목1, 항목2, ...}
wire [3:0] a = 4'b1010;
wire [3:0] b = 4'b0011;
wire [7:0] combined;

assign combined = {a, b};  // 8'b10100011
```

벡터의 일부나 상수도 결합할 수 있다.

```verilog
assign combined = {4'b0000, a};  // 8'b00001010: 상위 비트를 0으로 채움
```

위 두 assign은 **각각 별개의 사용 예**이며, 하나의 신호에 함께 적용하는 코드가 아니다.

결합을 대입의 왼쪽에 쓰면 하나의 값을 여러 신호로 나눠 받을 수도 있다. 아래는 모듈 내부에서 `a`, `b`, `cin`, `cout`, `sum`이 각각 1비트일 때의 전가산기 표현이다.

```verilog
assign {cout, sum} = {1'b0, a} + {1'b0, b} + {1'b0, cin};
```

입력을 2비트로 확장해 더하고, 결과의 상위 비트는 cout, 하위 비트는 sum에 연결한다. 논리 게이트로 표현한 식은 [[디지털 논리 회로/반가산기와 전가산기]]를 참고한다.

### 반복 연산자(Replication)

**같은 비트 패턴을 지정한 횟수만큼 복제하여 결합**한다. 반복 횟수는 상수 또는 parameter처럼 컴파일 시 결정되는 상수식이어야 한다.

```verilog
// 문법: {반복횟수{비트패턴}}
wire [7:0] pattern;
wire [3:0] ones;

assign pattern = {4{2'b10}};  // 8'b10101010: 2비트 × 4회
assign ones    = {4{1'b1}};  // 4'b1111: 1비트 × 4회
```

결합 연산자 안에서 반복 연산자를 함께 사용할 수 있다. 다음은 4비트 값의 최상위 비트를 복제하여 8비트로 **부호 확장**하는 비트 구성이다.

```verilog
wire [3:0] value = 4'b1010;
wire [7:0] extended;

assign extended = {{4{value[3]}}, value};  // 8'b11111010
```

이는 비트 패턴을 부호 확장한 것이다. 이후 부호 있는 산술 연산이 필요하면 대상 신호의 `signed` 선언도 별도로 고려한다.

### 핵심 구분과 주의점

- **결합**: 서로 다른 항목을 나열해 연결.
- **반복**: 같은 패턴을 여러 번 복제해 연결. `for`처럼 시간에 따라 실행을 반복하는 기능이 아니다.
- 상수는 `1'b0`, `4'b1010`처럼 **비트 폭을 명시**한다. 일반 결합 안에 폭 없는 숫자 상수를 넣지 않는다.
- 결과 폭과 받는 신호의 폭을 맞춘다. 받는 쪽이 좁으면 상위 비트가 잘릴 수 있다.

## 게이트 실습 코드

PDF의 Gates 모듈은 두 입력과 여섯 출력을 갖는 [[디지털 논리 회로/조합논리와 순차논리|조합논리 회로]]이다.

```verilog
`timescale 1ns / 1ps

module Gates(
    input a,
    input b,
    output ld0,
    output ld1,
    output ld2,
    output ld3,
    output ld4,
    output ld5
);
    assign ld0 = a & b;     // AND
    assign ld1 = a | b;     // OR
    assign ld2 = ~(a & b);  // NAND
    assign ld3 = ~(a | b);  // NOR
    assign ld4 = a ^ b;     // XOR
    assign ld5 = ~a;        // NOT
endmodule
```

**`assign`은 프로그램의 한 줄을 한 번 수행하는 대입이 아니라, 입력에 따라 출력이 계속 결정되는 회로 연결**로 이해한다. 각 줄은 실행 순서를 정하는 것이 아니라 서로 다른 출력의 논리를 표현한다.

- AND·OR·NAND·NOR: [[디지털 논리 회로/AND OR NAND NOR]]
- XOR: [[디지털 논리 회로/XOR과 XNOR]]
- NOT: [[디지털 논리 회로/NOT과 버퍼]]

## 블로킹과 논블로킹 할당

절차 블록에서 쓰는 할당 연산자는 구분해서 읽는다. 위 코드의 `assign`과는 맥락이 다르다.

| 연산자 | 동작을 읽는 기준 |
|---|---|
| `=` 블로킹 | 문장 순서대로 할당되어 앞의 결과가 뒤 문장에 영향을 줌 |
| `<=` 논블로킹 | 해당 이벤트에서 오른쪽 값을 평가하고 왼쪽 갱신을 예약 |

자료의 클록 기반 예시는 다음과 같다.

```verilog
always @(posedge reset or posedge clock) begin
    if (reset) begin
        flop1 <= 0;
        flop2 <= 1;
    end else begin
        flop1 <= flop2;
        flop2 <= flop1;
    end
end
```

리셋 후 `(flop1, flop2) = (0, 1)`이라면, 다음 클록에서 **이전 값을 기준으로 서로 교환**하여 `(1, 0)`이 된다. 핵심은 레지스터를 갱신할 때 다른 레지스터의 이전 값을 참조한다는 점이다.

테스트벤치의 순차적 입력 설정에서는 블로킹 할당을 사용한다. 관련 내용은 [[Vivado/테스트벤치와 시뮬레이션]]에서 확인한다.

### 블로킹: 작성 순서에 따라 결과가 달라짐

아래는 추가로 제공된 시프트 레지스터 비교 예제이다. 각 코드는 **서로 별개의 구현**이며, 지연문 없이 같은 블록 안에서 실행한다고 가정한다.

```verilog
always @(posedge clk) begin
    q0 = d;
    q1 = q0;
    q2 = q1;
    q3 = q2;
end
```

블로킹 할당은 **현재 문장의 값 갱신을 마친 뒤 다음 문장으로 진행**한다.

1. q0가 d로 갱신된다.
2. q1은 이미 갱신된 q0, 즉 d를 받는다.
3. q2와 q3도 앞에서 갱신된 값을 받아 결국 d가 된다.

**한 번의 상승 에지 처리 후 q0·q1·q2·q3가 모두 d가 된다.** 이전 값을 한 단계씩 옮기는 시프트 레지스터와 다르다.

반대로 순서를 뒤집으면 아직 갱신되지 않은 값을 읽는다.

```verilog
always @(posedge clk) begin
    q3 = q2;
    q2 = q1;
    q1 = q0;
    q0 = d;
end
```

- q3은 이전 q2를 받는다.
- q2는 이전 q1을 받는다.
- q1은 이전 q0를 받는다.
- 마지막에 q0가 d를 받는다.

이 블록만 보면 **한 에지마다 한 단계씩 이동하는 시프트 동작**이 된다. 다만 블로킹 할당으로 상태를 갱신하면 다른 클록 블록과의 실행 순서에 따른 경쟁 문제가 생길 수 있으므로, 순차회로의 상태 갱신에는 논블로킹 할당을 사용한다.

### 논블로킹: 이전 값을 읽고 갱신을 예약

```verilog
always @(posedge clk) begin
    q0 <= d;
    q1 <= q0;
    q2 <= q1;
    q3 <= q2;
end
```

각 문장이 실행될 때 **오른쪽 값을 먼저 평가하고, 왼쪽 값의 갱신은 같은 시뮬레이션 시각의 NBA(Nonblocking Assignment) 단계로 예약**한다. 위 블록에서는 q0의 갱신이 예약만 되어 있으므로 q1이 읽는 q0는 이전 값이다.

따라서 다음처럼 순서를 바꿔도 결과는 같다.

```verilog
always @(posedge clk) begin
    q3 <= q2;
    q2 <= q1;
    q1 <= q0;
    q0 <= d;
end
```

**이 예제처럼 서로 다른 왼쪽 변수에 한 번씩 할당하면 문장 순서와 관계없이 한 단계씩 이동한다.** 같은 변수에 여러 번 할당하는 경우까지 순서가 무관하다는 뜻은 아니다.

### 한 번의 상승 에지 결과 비교

에지 직전 값이 `(q0, q1, q2, q3) = (A, B, C, D)`이고 입력이 X라면 다음과 같다. A·B·C·D·X는 값을 구분하기 위한 기호이며, 미정 상태 `x`를 의미하지 않는다.

| 코드 | 갱신 후 (q0, q1, q2, q3) | 동작 |
|---|---|---|
| 블로킹, q0부터 작성 | (X, X, X, X) | 새 입력이 모두에 반영 |
| 블로킹, q3부터 작성 | (X, A, B, C) | 이전 값이 한 단계씩 이동 |
| 논블로킹, q0부터 작성 | (X, A, B, C) | 이전 값이 한 단계씩 이동 |
| 논블로킹, q3부터 작성 | (X, A, B, C) | 위와 동일 |

여기서 **즉시 갱신·예약은 시뮬레이터의 실행 규칙**이다. 블로킹 코드의 줄마다 실제 클록이 발생하거나, 물리 회로에서 신호가 지연 없이 전파된다는 뜻은 아니다. 플립플롭의 기본 동작은 [[디지털 논리 회로/조합논리와 순차논리#플립플롭과 래치|플립플롭과 래치]]와 연결해서 이해한다.

### 작성 기준

- **클록 기반 순차회로의 상태 갱신: `<=`**
- **조합논리의 절차적 계산: `=`**, 모든 조건에서 출력값을 할당
- **테스트벤치에서 순서대로 입력 자극 설정: `=`** — [[Vivado/테스트벤치 작성 지침]] 참고

## 회로 구조 확인과 재사용

`Open Elaborated Design`의 Schematic에서 코드가 어떤 게이트와 연결 구조로 해석됐는지 확인한다. 이는 [[Vivado/합성과 구현|최종 배치·배선 결과]]와는 다르다.

기존 모듈을 상위 모듈 안에 인스턴스화하면 하위 회로로 재사용할 수 있다. Gates를 DUT로 연결하는 named instantiation 예시는 [[Vivado/테스트벤치와 시뮬레이션]]에 있다. 보드 연결은 [[Vivado/XDC 핀 제약과 포트 매핑]]으로 지정한다.
