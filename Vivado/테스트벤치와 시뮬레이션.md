# 테스트벤치와 시뮬레이션

출처: PDF 52–61쪽 · [[Vivado/00 Vivado 디지털 회로 설계 길잡이|길잡이]]

## DUT와 테스트벤치

**테스트벤치(Testbench)는 검증할 회로에 입력을 주고 출력 결과를 관찰하는 시뮬레이션용 모듈**이다. 검증 대상 회로는 DUT(Design Under Test)라고 한다.

```text
테스트벤치
┌─────────────────────────────────────────────┐
│ 입력 생성(reg) → DUT → 출력 관찰(wire)       │
└─────────────────────────────────────────────┘
```

| 구분 | DUT | 테스트벤치 |
|---|---|---|
| 목적 | FPGA에서 동작할 실제 회로 | 가상 환경에서 회로 동작 검증 |
| 포트 | 회로의 입력·출력 포트 존재 | 이 실습의 테스트벤치에는 외부 입출력 포트 없음 |
| 기술 | 합성 가능한 assign·always 등 | initial·시간 지연 등 검증용 구문 사용 |
| 프로젝트 영역 | Design Sources | Simulation Sources |

자료의 테스트벤치는 DUT 입력을 구동할 신호를 `reg`, DUT 출력을 받을 신호를 `wire`로 선언한다. 소스 추가 방식은 [[Vivado/Vivado 환경 준비와 프로젝트 생성]]과 연결된다.

## initial과 timescale

**`initial` 블록은 시뮬레이션 시작 시 한 번 실행**되며, 이 실습에서는 블로킹 할당으로 입력을 순서대로 바꾼다. `#`은 다음 문장까지의 시뮬레이션 지연을 지정한다.

```verilog
`timescale 1ns / 10ps
```

- 앞의 값: 시간 단위. 위 설정에서 `#10`은 **10 ns**이다.
- 뒤의 값: 시간 정밀도. 위 설정은 **10 ps = 0.01 ns** 단위로 시간을 표현한다.
- **시간 단위와 정밀도는 다른 의미**이다.

PDF의 Gates 테스트벤치 코드는 `1ns / 1ps`를 사용한다.

## Gates 테스트벤치 코드

[[Vivado/Verilog 모듈과 게이트 회로|Gates 모듈]]을 별도 Design Source로 두고, 다음 코드를 Simulation Source로 추가한다. PDF 58쪽의 이름을 구분한 예제를 정리했다.

```verilog
`timescale 1ns / 1ps

module testbench_gates();
    reg i_a;
    reg i_b;
    wire o_ld0;
    wire o_ld1;
    wire o_ld2;
    wire o_ld3;
    wire o_ld4;
    wire o_ld5;

    Gates dut(
        .a(i_a),
        .b(i_b),
        .ld0(o_ld0),
        .ld1(o_ld1),
        .ld2(o_ld2),
        .ld3(o_ld3),
        .ld4(o_ld4),
        .ld5(o_ld5)
    );

    initial begin
        #0  i_a = 1'b0; i_b = 1'b0;
        #10 i_a = 1'b0; i_b = 1'b1;
        #10 i_a = 1'b1; i_b = 1'b0;
        #10 i_a = 1'b1; i_b = 1'b1;
        #10 $finish;
    end
endmodule
```

### 모듈 연결을 읽는 방법

- `Gates`: 사용할 모듈 이름.
- `dut`: 이 테스트벤치 안에서의 인스턴스 이름.
- `.a(i_a)`: **DUT 포트 a에 테스트벤치 신호 i_a를 연결**.
- 이처럼 포트 이름을 직접 지정하는 방식을 named instantiation이라고 한다.
- `1'b0`: 1비트 이진수 0.
- `$finish`: 시뮬레이션 종료.

테스트벤치 신호 이름과 DUT 포트 이름은 달라도 된다. [[Vivado/XDC 핀 제약과 포트 매핑|XDC]]는 테스트벤치 신호가 아니라 보드에 구현할 설계 포트를 대상으로 한다.

## 입력 시간과 예상 출력

각 `#10`은 직전 단계에서 10 ns 더 기다린다는 뜻이다. 네 입력 조합을 모두 확인한다.

| 시간 구간 | a b | ld0 AND | ld1 OR | ld2 NAND | ld3 NOR | ld4 XOR | ld5 NOT a |
|---|---|---|---|---|---|---|---|
| 0–10 ns | 0 0 | 0 | 0 | 1 | 1 | 0 | 1 |
| 10–20 ns | 0 1 | 0 | 1 | 1 | 0 | 1 | 1 |
| 20–30 ns | 1 0 | 0 | 1 | 1 | 0 | 1 | 0 |
| 30–40 ns | 1 1 | 1 | 1 | 0 | 0 | 0 | 0 |

40 ns에서 `$finish`로 종료한다. 파형을 [[디지털 논리 회로/AND OR NAND NOR|게이트 진리표]]와 비교해 각 구간이 맞는지 확인한다.

## 시뮬레이션 실행과 파형 확인

1. `Add Sources` → `Add or Create Simulation Sources`에서 테스트벤치를 생성한다.
2. 검증할 모듈을 DUT로 연결하고 입력 자극을 작성한다.
3. `Run Simulation` → `Run Behavioral Simulation`을 실행한다.
4. 파형에서 입력 변경 시점과 출력 값을 확인한다.
5. 전체 구간이 보이도록 파형을 확대·축소하고 원하는 시간에 커서를 놓아 값을 읽는다.

코드를 수정한 뒤에는 시뮬레이션을 다시 실행하여 변경 결과를 확인한다. 파형 확대·별도 창 사용은 [[Vivado/Vivado 2022.2 유용한 단축키]]를 참고한다. 검증 후 실제 보드 확인은 [[Vivado/비트스트림과 보드 프로그래밍]]으로 이어진다.
